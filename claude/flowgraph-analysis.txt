1. ARCHITECTURE OVERVIEW
================================================================================

The FlowGraph module implements a visual scripting / flow-based programming
system for Babylon.js. The architecture follows a clear hierarchy:

  FlowGraphCoordinator (manages multiple FlowGraphs per scene)
    └─ FlowGraph (a single graph with blocks and contexts)
         ├─ FlowGraphContext (execution context / runtime state)
         ├─ FlowGraphBlock (base class for all blocks)
         │    ├─ FlowGraphExecutionBlock (blocks triggered by signals)
         │    │    ├─ FlowGraphExecutionBlockWithOutSignal (has "out" signal)
         │    │    │    └─ FlowGraphAsyncExecutionBlock (has "done" signal)
         │    │    │         └─ FlowGraphEventBlock (entry points)
         │    │    └─ Direct subclasses (BranchBlock, MultiGateBlock, etc.)
         │    └─ Data blocks (pure functions, no signals)
         ├─ FlowGraphConnection (base for data/signal connections)
         │    ├─ FlowGraphDataConnection<T> (typed data flow)
         │    └─ FlowGraphSignalConnection (execution flow)
         └─ Supporting: Validator, Parser, Logger, PathConverter, etc.

Key design patterns:
  - Observer pattern for event propagation
  - Strategy pattern for polymorphic math operations
  - Factory pattern for block creation (FlowGraphBlockFactory)
  - Context-based execution variables for block state

3. VERIFIED BUGS & ERRORS (FIXES APPLIED)
================================================================================

BUG-1: Wrong error messages in math blocks
  File: Blocks/Data/Math/flowGraphMathBlocks.ts
  Lines: 119, 176, 243
  Issue: Subtract, Multiply, and Divide blocks all say "Cannot add different
         types of numbers" — copy-paste error from the Add block.
  Fix: Changed to "Cannot subtract/multiply/divide different types of numbers"
       respectively.

BUG-2: Constructor early return in DataSwitchBlock
  File: Blocks/Data/flowGraphDataSwitchBlock.ts
  Line: 65
  Issue: `return;` exits the ENTIRE constructor when a duplicate integer case
         is found, leaving the block in an incomplete state. Should be
         `continue;` to skip only the duplicate case and process remaining ones.
  Fix: Changed `return` to `continue`.

BUG-3: Falsy value treated as no-match in DataSwitchBlock
  File: Blocks/Data/flowGraphDataSwitchBlock.ts
  Line: 78
  Issue: `if (!outputValue)` treats falsy values (0, false, empty string) as
         "no match found," falling through to default. Valid matched values
         of 0, false, or "" would be incorrectly ignored.
  Fix: Changed to `if (outputValue === undefined)`.

BUG-4: Wrong config property name in InterpolationBlock
  File: Blocks/Execution/Animation/flowGraphInterpolationBlock.ts
  Line: 145
  Issue: `this.config?.numberOfKeyFrames` references a property that doesn't
         exist on IFlowGraphInterpolationBlockConfiguration. The correct
         property name is `keyFramesCount`.
  Fix: Changed to `this.config?.keyFramesCount`.

BUG-5: Missing easing function implementations
  File: Blocks/Execution/Animation/flowGraphEasingBlock.ts
  Lines: 36-55
  Issue: The EasingFunctionType enum defines PowerEase (6), QuadraticEase (7),
         QuarticEase (8), QuinticEase (9), and SineEase (10), but the
         CreateEasingFunction switch statement has no cases for them. At runtime
         these fall through to `throw new Error("Easing type not yet implemented")`.
  Fix: Added missing case implementations using the corresponding Babylon.js
       easing classes.

BUG-6: Serialization property name mismatch in MultiGateBlock
  File: Blocks/Execution/ControlFlow/flowGraphMultiGateBlock.ts
  Line: 133
  Issue: `serializationObject.config.loop = this.config.isLoop` serializes
         the property as "loop" but the config interface defines it as "isLoop".
         Deserialization will fail to restore this property.
  Fix: Changed to `serializationObject.config.isLoop = this.config.isLoop`.

BUG-7: DFS cycle detection ignores recursive return value
  File: flowGraphValidator.ts
  Line: 372
  Issue: `dfs(dep)` is called without using its return value. If a cycle is
         detected in a deeper recursive call, the current call doesn't know
         about it and continues exploring, potentially marking nodes as fully
         explored (black) when they're part of a cycle path. This can cause
         some cycles to go unreported.
  Fix: Added `if (dfs(dep)) return true;` to propagate cycle detection.

BUG-8: ForLoop MaxLoopIterations check incorrect for negative step
  File: Blocks/Execution/ControlFlow/flowGraphForLoopBlock.ts
  Line: 90
  Issue: `if (i > FlowGraphForLoopBlock.MaxLoopIterations * step)` — when
         step is negative, MaxLoopIterations * step is negative, so the
         condition is always true on first iteration, breaking immediately.
         Should use absolute value of step or simply count iterations.
  Fix: Added an iteration counter and check against MaxLoopIterations directly.

BUG-9: Debugging artifact comment
  File: Blocks/Execution/Animation/flowGraphInterpolationBlock.ts
  Line: 182
  Issue: `// #L54P2C` is a leftover debugging artifact.
  Fix: Removed the comment.

BUG-10: `==` instead of `===` in SetVariableBlock
  File: Blocks/Execution/flowGraphSetVariableBlock.ts
  Line: 59
  Issue: `animationGroup.uniqueId == animationUniqueId` uses loose equality.
         Both values are numbers, so this works but is inconsistent with the
         rest of the codebase which uses strict equality.
  Fix: Changed to `===`.

4. OPTIMIZATIONS & IMPROVEMENTS (FIXES APPLIED)
================================================================================

None applied — the above section focused exclusively on concrete bugs that
could cause incorrect behavior at runtime. Performance optimizations and code
quality improvements were noted but left for the team to evaluate:

  - Math block polymorphic dispatch could use strategy maps instead of if-else
  - Object pooling for FlowGraphInteger in hot loops (ForLoop, Counter)
  - Caching regex compilation in ConsoleLogBlock
  - Static PathHasTemplatesRegex in flowGraphPathConverterComponent.ts
  - Extracting duplicated validation logic in flowGraphValidator.ts

5. ADDITIONAL OBSERVATIONS (NOT FIXED)
================================================================================

a) The FlipFlop block (flowGraphFlipFlopBlock.ts:46) initializes its default
   value as `!startValue` so the first toggle produces `startValue`. This is
   intentional but non-obvious — worth a clarifying comment.

b) The WhileLoop and ForLoop blocks use static MaxLoopCount/MaxLoopIterations.
   A per-instance override via config could be useful for specialized use cases.

c) Audio blocks don't validate volume ranges (0-1) or negative offsets. The
   underlying audio engine may handle this, but input validation would provide
   better error messages.

d) The block factory (flowGraphBlockFactory.ts) is a large switch statement
   (~360 lines). A registry pattern would improve extensibility and tree-shaking.

e) Several pointer event blocks share identical mesh-filtering logic that
   could be extracted into a shared utility.

f) The easing function cache in FlowGraphEasingBlock uses string keys built
   from parameters. For very large parameter arrays this could be slow.

g) Type safety: Many blocks use RichTypeAny where more specific types would
   catch errors at graph-build time rather than runtime.
