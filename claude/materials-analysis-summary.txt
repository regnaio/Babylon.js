BUGS FOUND AND FIXED

--- BUG 1 (HIGH): materialFlags.ts:350 ---
RefractionIntensityTextureEnabled getter returns wrong backing field
  Getter returns this._ThicknessTextureEnabled instead of
  this._RefractionIntensityTextureEnabled. This is a copy-paste bug that causes:
  - Reading RefractionIntensityTextureEnabled returns the value of
    ThicknessTextureEnabled
  - Setting RefractionIntensityTextureEnabled = false appears to have no effect
    when read back
  FIX: Changed getter to return this._RefractionIntensityTextureEnabled.

--- BUG 2 (HIGH): materialHelper.functions.ts:1099 ---
Inconsistent morph target define name
  The else branch uses "MORPHTARGETTEXTURE_HAS_COLORS" (with extra underscore)
  while the if branch uses "MORPHTARGETTEXTURE_HASCOLORS" (no underscore). This
  means when there is no morph target manager, the correct define is never reset
  to false, and a stale true value from a previous manager could persist.
  FIX: Changed "MORPHTARGETTEXTURE_HAS_COLORS" to "MORPHTARGETTEXTURE_HASCOLORS".

--- BUG 3 (HIGH): meshDebugPluginMaterial.ts:181-183 ---
WGSL shader uses GLSL "float" keyword instead of WGSL "var"
  In fragmentDefinitionsWebGPU, the dbg_cornerFactor() function uses GLSL syntax:
    float dist = ...; float camDist = ...; float d = ...;
  These should be "var dist", "var camDist", "var d" as used everywhere else in
  the WGSL code. This will produce a shader compilation error on WebGPU.
  FIX: Changed all three "float" declarations to "var".

--- BUG 4 (HIGH): meshDebugPluginMaterial.ts:192 ---
WGSL shader uses unsupported ternary operator
  The dbg_checkerboardFactor function uses GLSL ternary syntax:
    return (f.x * f.y) > 0. ? 1. : 0.;
  WGSL does not support the ?: operator. Must use select() instead.
  FIX: Changed to: return select(0., 1., (f.x * f.y) > 0.);

--- BUG 5 (MEDIUM): meshDebugPluginMaterial.ts:236 ---
WGSL uses GLSL vec3() instead of WGSL vec3f()
  Line 236: vec3(1.) should be vec3f(1.) in WGSL context.
  FIX: Changed vec3(1.) to vec3f(1.).

--- BUG 6 (MEDIUM): meshDebugPluginMaterial.ts:254 ---
WGSL missing uniforms. prefix on dbg_shadedDiffuseColor
  In WGSL, uniform variables must be accessed via "uniforms." prefix. The
  reference to dbg_shadedDiffuseColor is missing this prefix.
  FIX: Changed dbg_shadedDiffuseColor to uniforms.dbg_shadedDiffuseColor.

--- BUG 7 (MEDIUM): shaderMaterial.ts:1358-1367 ---
clone() modifies source material's options instead of clone's options
  The clone() method operates on this._options when it should operate on
  result._options, meaning the clone shares array references with the original
  and the source's options get unnecessarily shallow-copied.
  FIX: Changed all this._options references to result._options in the clone block.

--- BUG 8 (MEDIUM): colorCurves.ts:252-255 ---
Missing @serialize() decorators on shadow color curve properties
  The four _shadows* fields (_shadowsHue, _shadowsDensity, _shadowsSaturation,
  _shadowsExposure) lack @serialize() decorators while all equivalent fields in
  _global*, _highlights*, and _midtones* have them. This means shadow color
  curve settings are silently lost during serialization/deserialization.
  FIX: Added @serialize() decorators to all four _shadows* fields.

--- BUG 9 (MEDIUM): material.ts:1661-1671 ---
forceCompilation calls both onError AND onCompiled when compilation fails
  When there is a lastError, both the onError callback and the onCompiled
  callback are invoked. These should be mutually exclusive.
  FIX: Changed onCompiled call to only execute when there is no error (else if).

--- BUG 10 (MEDIUM): fresnelParameters.ts:179 ---
power=0 cannot be round-tripped through serialize/parse
  Uses || instead of ?? for the power fallback, meaning a serialized power
  value of 0 would be incorrectly deserialized as 1.0.
  FIX: Changed || to ??.

--- BUG 11 (LOW): effect.ts:1352 ---
Incorrect comment references wrong GL function
  Comment says "gl.uniformMatrix3fv()" but the method is setMatrix2x2, which
  calls gl.uniformMatrix2fv().
  FIX: Changed comment to reference uniformMatrix2fv.

--- BUG 12 (LOW): materialFlags.ts:395 ---

================================================================================
FINDINGS NOTED BUT NOT FIXED (design decisions / lower priority)
================================================================================

1. drawWrapper.ts: Non-immediate dispose via onEndFrameObservable.addOnce may
   never fire if engine is shutting down, potentially leaking effects. This is a
   design trade-off between immediate disposal and frame-end cleanup.

2. effect.ts: _uniformBuffersNamesList potentially uninitialized when using
   IEffectCreationOptions without uniformBuffersNames. Would require API change.

3. uniformBuffer.ts: Throws string literals instead of Error objects in multiple
   places (acknowledged by eslint-disable comments). Would require broader
   codebase style decision.

4. materialDefines.ts: [id: string]: any index signature defeats type safety for
   dynamic defines. This is a fundamental design choice enabling the flexible
   define system.

5. shadowDepthWrapper.ts: dispose() does not clean up _subMeshToEffect or
   _subMeshToDepthWrapper entries, potentially leaking depth effects. Would need
   design review.

6. uniformBufferEffectCommonAccessor.ts: Missing unsigned integer methods
   (setUInt, setUInt2, etc.). This is an API completeness gap.

7. vertexPullingHelper.functions.ts: Cache validation doesn't detect changes to
   existing vertex buffer properties or removal of vertex buffers. Would need
   cache invalidation redesign.

8. material.ts: markDirty() and _markAllSubMeshesAsDirty() iterate all scene
   meshes instead of using meshMap. Would need performance profiling to confirm
   benefit.

9. standardMaterial.ts: new Color3() allocation in hot path for opacity fresnel
   binding. Would need a pre-allocated temporary pattern.

10. effectRenderer.ts: Floating promise on waitImportsLoaded?.() with eslint
    disable comment. Error handling design decision.
