PostProcesses Directory Analysis Summary
=========================================

Analyzed all 77 TypeScript files in packages/dev/core/src/PostProcesses/ including
the RenderPipeline subdirectory and all Pipelines. For each file, traced its imports
and the files that import it to understand interactions.

Files Analyzed:
- postProcess.ts (core base class, ~1292 lines)
- postProcessManager.ts (manages post-process chains)
- All individual post-process implementations (blur, bloom, DOF, FXAA, grain, etc.)
- All "thin" variants (thinBlurPostProcess, thinBloomEffect, etc.)
- RenderPipeline infrastructure (postProcessRenderEffect, postProcessRenderPipeline, etc.)
- Pipeline implementations (default, standard, SSAO, SSAO2, SSR, TAA, lens)
- VR-related post processes
- Stereoscopic post processes

BUGS FOUND AND FIXED
================================================================================

1. [BUG] screenSpaceCurvaturePostProcess.ts - _Parse swapped arguments
   File: screenSpaceCurvaturePostProcess.ts, lines 134-152
   Description: In the static _Parse method, the arguments `textureType` and
   `reusable` were passed to the constructor in the wrong order. The constructor
   signature is (..., reusable?, textureType?, blockCompilation?) but _Parse was
   passing (..., textureType, reusable), effectively swapping their values.
   This means deserialized ScreenSpaceCurvaturePostProcess instances would have
   incorrect texture type and reusability settings.

2. [BUG] screenSpaceReflectionPostProcess.ts - _Parse swapped arguments
   File: screenSpaceReflectionPostProcess.ts, lines 288-306
   Description: Same issue as #1. The _Parse method passes textureType where
   reusable should be and vice versa. Constructor signature is
   (..., reusable?, textureType?, blockCompilation?, forceGeometryBuffer?) but
   _Parse passes (..., textureType, reusable).

3. [BUG] sharpenPostProcess.ts - _Parse swapped arguments
   File: sharpenPostProcess.ts, lines 102-118
   Description: Same issue as #1 and #2. The _Parse method passes textureType
   where reusable should be and reusable where textureType should be.

4. [BUG] postProcessRenderPipeline.ts - Array splice index shift bug
   File: postProcessRenderPipeline.ts, lines 175-177
   Description: When removing duplicate cameras from the `cams` array, the code
   collects indices to delete and then splices them out in forward order. However,
   each splice shifts subsequent array indices down by one, causing later splices
   to remove the wrong elements. For example, if indices [2, 5] need removal:
   after splicing index 2, the element previously at index 5 is now at index 4,
   so `splice(5, 1)` removes the wrong element.
   Fix: Iterate in reverse order when splicing.

5. [BUG] postProcess.ts - Typo in onAfterRender callback parameter
   File: postProcess.ts, line 494
   Description: The callback parameter for onAfterRender setter is named `efect`
   instead of `effect`. While this doesn't cause a runtime error since it's just
   a parameter name, it appears in the public API documentation/type information.

IMPROVEMENTS FOUND AND FIXED
================================================================================

6. [IMPROVEMENT] vrMultiviewToSingleviewPostProcess.ts - Dead code removal
   File: vrMultiviewToSingleviewPostProcess.ts, line 33
   Description: An empty callback `this.onSizeChangedObservable.add(() => {})` is
   registered that does nothing. This is dead code and was removed.

7. [IMPROVEMENT] postProcess.ts - Comment typo fixes
   File: postProcess.ts, line 941 and 1082
   Description: Fixed typos "intializing" -> "initializing" and "preivous" ->
   "previous" in code comments.

8. [OPTIMIZATION] fxaaPostProcess.ts - Unnecessary heavy Texture import
   File: fxaaPostProcess.ts, line 4
   Description: The `Texture` class was imported solely to access
   `Texture.BILINEAR_SAMPLINGMODE`. The identical constant is available as
   `Constants.TEXTURE_BILINEAR_SAMPLINGMODE` from the already-imported `Constants`
   class. Using `Constants` avoids pulling the entire Texture class into the bundle
   for tree-shaking purposes.

9. [OPTIMIZATION] sharpenPostProcess.ts - Redundant side-effect shader import
   File: sharpenPostProcess.ts, line 7
   Description: The side-effect import `import "../Shaders/sharpen.fragment"` eagerly
   loads the GLSL shader. However, ThinSharpenPostProcess already dynamically imports
   the shader (both GLSL and WGSL variants) in its _gatherImports method. This import
   was redundant and forced the GLSL shader to always be bundled even when only WebGPU
   is used.

10. [IMPROVEMENT] highlightsPostProcess.ts - Missing RegisterClass call
    File: highlightsPostProcess.ts
    Description: Every other PostProcess in the directory registers itself with
    `RegisterClass("BABYLON.<ClassName>", <ClassName>)` for deserialization support.
    HighlightsPostProcess was the only one missing this, meaning it could not be
    properly deserialized from serialized scene data.

11. [BUG] thinColorCorrectionPostProcess.ts - LUT texture resource leak
    File: thinColorCorrectionPostProcess.ts
    Description: The constructor creates a `Texture` for the color LUT table, but
    there was no `dispose()` override to clean it up. Disposing the post process
    would leak the color table texture. Added a dispose override that cleans up
    the texture before calling super.dispose().

================================================================================
OTHER OBSERVATIONS (NOT FIXED - by design or low risk)
================================================================================

- depthOfFieldBlurPostProcess.ts:66 - The samplingMode parameter is silently
  overridden with TEXTURE_BILINEAR_SAMPLINGMODE via an assignment inside the
  options object. Has eslint-disable comment indicating it's intentional.

- stereoscopicInterlacePostProcess.ts - Both classes compute
  `new Vector2(1 / this.width, 1 / this.height)` in constructor when width/height
  are still -1, resulting in Vector2(-1, -1). This is harmless because the
  onSizeChangedObservable callback corrects it when actual dimensions are set.

- postProcessManager.ts:97 - `postProcesses !== null && postProcesses !== undefined`
  always evaluates to true at that point (since null/undefined was already checked),
  meaning forceDepthStencil is always true in _prepareFrame. This appears intentional
  as a safety measure for the initial render pass.

- subSurfaceScatteringPostProcess.ts:74-77 - Uses non-null assertion on
  scene.activeCamera without checking. While technically could crash if no active
  camera, subsurface scattering inherently requires a camera to function.

- thinSSAO2PostProcess.ts:188 - _randomTexture.dispose() could throw if
  _createRandomTexture failed, but in practice the constructor always calls it
  synchronously so the texture is always initialized.

- motionBlurPostProcess.ts:230 - The condition checking _forcedGeometryBuffer
  is confusing (checks the nullable instance, not the boolean flag) but logically
  correct in all code paths.

- The "thin" variants (thinBlurPostProcess, thinBloomEffect, etc.) serve as the
  underlying implementation that the regular post processes delegate to. This pattern
  is consistent and well-structured throughout the codebase.

- The RenderPipeline infrastructure is well-organized with clear separation between
  effects, pipelines, and the pipeline manager.

12. [BUG] vrDistortionCorrectionPostProcess.ts - Uninitialized fields can crash
    File: vrDistortionCorrectionPostProcess.ts, lines 18-20
    Description: _scaleIn, _scaleFactor, and _lensCenter were only initialized inside
    onSizeChangedObservable. If onApplyObservable fired before onSizeChanged (before
    the first resize event), accessing .x/.y on undefined would throw a runtime error.
    Fixed by initializing with default Vector2 values.

13. [BUG] volumetricLightScatteringPostProcess.ts - Stale viewport after engine resize
    File: volumetricLightScatteringPostProcess.ts, line 160 and 613-633
    Description: _viewPort was computed once in the constructor using engine dimensions.
    If the canvas/engine was resized after construction, the stale viewport would cause
    incorrect screen coordinate calculations for the light source position, making the
    light scattering effect appear offset after a window resize. Fixed by recomputing
    the viewport each frame in _updateMeshScreenCoordinates.

14. [IMPROVEMENT] screenSpaceReflectionPostProcess.ts - Inconsistent import path
    File: screenSpaceReflectionPostProcess.ts, line 18
    Description: Changed from non-portable "core/Misc/logger" import path to relative
    "../Misc/logger" for consistency with all other imports in the file.

    Description: Used this._camera._getFirstPostProcess() instead of the local

    Description: TEXTURE_LINEAR_NEAREST (mode 12) has no mipmaps but wasn't

27. [BUG] depthOfFieldEffect.ts - depthNotNormalized hardcoded to false
    File: depthOfFieldEffect.ts, line 116
    Description: The depthNotNormalized constructor parameter was not forwarded to
    ThinDepthOfFieldEffect - it was hardcoded as false. This meant the
    #define COC_DEPTH_NOT_NORMALIZED was never set, producing incorrect depth of
    field rendering when depth values are not normalized.

28. [IMPROVEMENT] thinBlurPostProcess.ts - _glslFloat trailing decimal point
    File: thinBlurPostProcess.ts, line 293-294
    Description: The regex /0+$/ stripped ALL trailing zeros, producing values like
    "1." for whole numbers. While technically valid GLSL, some shader compilers may
    reject this. Changed to ensure at least one digit after the decimal point.

29. [BUG] thinPassPostProcess.ts - Constructor spread order reversed
    File: thinPassPostProcess.ts, lines 32-45
    Description: ...options was spread LAST, meaning user-provided options could
    override hardcoded properties like fragmentShader and useAsPostProcess. All
    other thin post processes (ThinPassCube, ThinCustom, ThinImageProcessing)
    spread options FIRST and hardcoded values AFTER. Also removed dead code:
    the null check for engine after the spread was unreachable.

30. [BUG] thinTAAPostProcess.ts - _reset() passes zero dimensions to Halton sequence
    File: thinTAAPostProcess.ts, line 197
    Description: _reset() is called from disabled and reprojectHistory setters,
    which can fire before texture dimensions are set (both default to 0). Passing
    0/0 to Halton2DSequence.setDimensions produces degenerate jitter offsets.
    Added guard to only set dimensions when they are valid.
