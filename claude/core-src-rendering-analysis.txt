CONFIRMED BUGS FIXED (7 issues)
================================================================================

1. [BUG] subSurfaceConfiguration.ts:132 — Swapped color components (r,b,g vs r,g,b)
   Severity: CRITICAL
   File: subSurfaceConfiguration.ts, line 132
   Description: When adding a new diffusion profile, the color components are
   pushed in (r, b, g) order instead of (r, g, b). The duplicate detection at
   line 127 checks in (r, g, b) order, creating a mismatch. This causes:
     a) Duplicate detection to always fail (same color can be added multiple times)
     b) Incorrect color data sent to shaders via setArray3("diffusionS"), causing
        green and blue channels to be swapped in subsurface scattering calculations

2. [BUG] subSurfaceSceneComponent.ts:93 — Wrong component name constant
   Severity: CRITICAL
   File: subSurfaceSceneComponent.ts, line 93
   Description: The component registers with NAME_PREPASSRENDERER ("PrePassRenderer")
   but the initialization function at line 173 looks it up using NAME_SUBSURFACE
   ("SubSurface"). This mismatch means scene._getComponent() never finds the
   existing component, causing a new SubSurfaceSceneComponent to be created every
   time SubSurfaceConfiguration is instantiated.

3. [MEMORY LEAK] utilityLayerRenderer.ts:347/406 — Observer added to wrong observable
   Severity: CRITICAL
   File: utilityLayerRenderer.ts, lines 347 and 406
   Description: At line 347, _afterRenderObserver is added to
   onAfterRenderCameraObservable (fires for each sub-camera in a rig). But in
   dispose() at line 406, it's removed from onAfterCameraRenderObservable (fires
   for the full rig camera only). These are two DIFFERENT observables on the Scene
   class, so the observer is never properly removed, causing a memory leak.

4. [MEMORY LEAK] thinDepthPeelingRenderer.ts:581-587 — Missing EffectWrapper disposal
   Severity: HIGH
   File: thinDepthPeelingRenderer.ts, dispose() method
   Description: The dispose() method disposes _blendBackEffectWrapper and
   _finalEffectWrapper, but omits _blendBackEffectWrapperPingPong. This
   EffectWrapper and its associated GPU resources (Effect, shader programs) are
   never released when the renderer is disposed.

5. [MEMORY LEAK] edgesRenderer.ts:358 — Index buffer leak on rebuild
   Severity: HIGH
   File: edgesRenderer.ts, _rebuild() method, line 358
   Description: When _rebuild() is called (e.g., on context loss or geometry
   change), a new index buffer is created and assigned to this._ib without
   first releasing the existing one. The old GPU buffer is orphaned. Only the
   final buffer is released in dispose().

6. [MEMORY LEAK] geometryBufferRenderer.ts:424-437 — Bones matrices not cleared
   Severity: MEDIUM
   File: geometryBufferRenderer.ts, enableVelocity setter
   Description: When velocity is disabled, _previousTransformationMatrices is
   cleared (line 428) but _previousBonesTransformationMatrices is not. This
   causes accumulated Float32Array instances for skinned meshes to persist in
   memory indefinitely.

7. [NAMING] prePassRendererSceneComponent.ts:117 — Wrong step constant name
   Severity: LOW (functionally identical since both constants equal 0)
   File: prePassRendererSceneComponent.ts, line 117
   Description: Uses STEP_AFTERCAMERADRAW_PREPASS for _afterRenderTargetDrawStage
   when it should use STEP_AFTERRENDERTARGETDRAW_PREPASS to match the naming
   pattern. Line 116 correctly uses STEP_BEFORERENDERTARGETDRAW_PREPASS for
   _beforeRenderTargetDrawStage.

ADDITIONAL FINDINGS (not fixed — require further investigation)
================================================================================

These issues were identified during analysis but are either too risky to change
without deep testing, are in complex subsystems, or have uncertain impact:

A. boundingBoxRenderer.ts — BoundingBox DrawWrappers may not be fully disposed
   when individual bounding boxes are removed from the render list. The
   _drawWrapperFront and _drawWrapperBack on BoundingBox instances are created
   by the renderer but their lifecycle is tied to the bounding box, not the
   renderer.

B. renderingGroup.ts:479,502 — Operator precedence in layer mask checks could
   behave unexpectedly when activeCamera is null/undefined, though this edge
   case likely never occurs in practice.

C. outlineRenderer.ts — Scene component steps registered in register() are never
   unregistered in dispose(). The steps reference `this`, which could cause
   callbacks on a disposed renderer.

D. fluidRenderingTargetRenderer.ts — Blur post process disposal pattern stores
   the same objects at multiple array indices, making cleanup fragile.

E. iblShadowsVoxelRenderer.ts — Multiple potential issues including variable
   shadowing, listener accumulation in updateVoxelGrid(), and a TODO for
   incomplete disposal.

F. giRSMManager.ts — _sampleTexture may not be disposed in all code paths.
   _ppGlobalIllumination array accessed without bounds check.

G. reflectiveShadowMap.ts — Cloned materials created during RSM generation may
   not be properly disposed in all scenarios.
