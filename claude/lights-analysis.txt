ISSUES FOUND
================================================================================

BUG 1 (CRITICAL): shadowGenerator.ts serialize() - Wrong property references
  File: Shadows/shadowGenerator.ts, lines 2199-2200
  The serialize() method writes:
    serializationObject.useCloseExponentialShadowMap = this.useBlurExponentialShadowMap;
    serializationObject.useBlurCloseExponentialShadowMap = this.useBlurExponentialShadowMap;
  Both should reference their own property:
    serializationObject.useCloseExponentialShadowMap = this.useCloseExponentialShadowMap;
    serializationObject.useBlurCloseExponentialShadowMap = this.useBlurCloseExponentialShadowMap;
  Impact: Serializing a ShadowGenerator that uses CloseESM or BlurCloseESM
  will serialize the wrong filter type. On deserialization, the wrong filter
  would be restored.

BUG 2 (MINOR): light.ts toString() - Wrong animation index in string
  File: light.ts, line 499
  The loop iterates with `i` but always prints "animation[0]" instead of
  "animation[i]". This is a copy-paste bug in a debug string.

BUG 3 (MINOR): light.ts canAffectMesh() - Missing parentheses in bitwise check
  File: light.ts, line 574
  The condition `this.excludeWithLayerMask !== 0 && this.excludeWithLayerMask & mesh.layerMask`
  relies on operator precedence where `&` has lower precedence than `!==`.
  While the result is technically correct because `!==` evaluates first,
  the missing parentheses around the bitwise `&` result make intent unclear
  and is inconsistent with the includeOnlyWithLayerMask check on line 570
  which correctly uses `(this.includeOnlyWithLayerMask & mesh.layerMask) === 0`.

BUG 4 (MINOR): lightConstants.ts - Typo in JSDoc comment
  File: lightConstants.ts, line 1
  "constantsused" should be "constants used" (missing space).

BUG 5 (COSMETIC): hemisphericLight.ts transferToEffect - Allocates new Vector3 per call
  File: hemisphericLight.ts, line 93
  `Vector3.Normalize(this.direction)` allocates a new Vector3 each call.
  Should use `Vector3.NormalizeToRef` with a temp vector. Same issue on
  line 100 in transferToNodeMaterialEffect. This is called every render
  frame for every mesh affected by this light.

BUG 6 (COSMETIC): hemisphericLight.ts transferToEffect - groundColor not scaled correctly
  File: hemisphericLight.ts, line 95
  `this.groundColor.scale(this.intensity)` allocates a new Color3 and uses
  raw intensity instead of getScaledIntensity(). The diffuse/specular colors
  in the base class _bindLight use getScaledIntensity() which factors in
  photometric scale. The groundColor should be consistent, but this appears
  intentional for hemispheric lights since they always have photometricScale=1.
  However, the allocation of a new Color3 each frame is wasteful.

BUG 7 (COSMETIC): areaLight.ts - Typo in class JSDoc
  File: areaLight.ts, line 67
  "servers" should be "serves".
